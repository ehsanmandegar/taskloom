# راهنمای سیستم چند-ارائه‌دهنده AI در TaskLoom

## مقدمه

TaskLoom اکنون از یک سیستم چند-ارائه‌دهنده (Multi-Provider) پشتیبانی می‌کند که به شما امکان می‌دهد:
- از ارائه‌دهندگان مختلف AI استفاده کنید: Ollama (محلی)، Codex CLI، Claude CLI
- برای هر مرحله SDLC (تحلیل، بک‌اند، فرانت‌اند، n8n، تست) ارائه‌دهنده و مدل مستقل انتخاب کنید
- کدنویسی واقعی با هر یک از این ارائه‌دهندگان انجام دهید
- بین ارائه‌دهندگان محلی (Ollama) و ابری (Codex/Claude) سوئیچ کنید

## ارائه‌دهندگان پشتیبانی‌شده

### 1. Ollama (محلی)
- **نوع**: LLM محلی
- **مزایا**: بدون هزینه، حریم خصوصی کامل، کنترل محلی
- **مدل‌های پیشنهادی**: Qwen3.5, Llama 3.1, Mistral, Gemma
- **نصب**: از [ollama.com](https://ollama.com) دانلود کنید

### 2. Codex CLI  
- **نوع**: OpenAI coding agent via CLI
- **مزایا**: قدرتمند برای کدنویسی، پشتیبانی از MCP servers
- **نصب**: Codex CLI را نصب و با حساب خود sign in کنید

### 3. Claude CLI
- **نوع**: Anthropic Claude via CLI
- **مزایا**: قدرتمند برای تحلیل و کدنویسی، reasoning پیشرفته
- **نصب**: Claude Code CLI را نصب و با حساب خود sign in کنید

## نصب و راه‌اندازی

### 1. نصب Ollama
ابتدا Ollama را از [ollama.com](https://ollama.com) نصب کنید.

### 2. دانلود مدل‌ها
مدل‌های مورد نیاز خود را دانلود کنید:

```bash
# مدل پیش‌فرض
ollama pull qwen3.5:0.8b

# مدل‌های دیگر (اختیاری)
ollama pull llama3.1:8b
ollama pull mistral:7b
ollama pull gemma:7b
```

### 3. اجرای TaskLoom
TaskLoom به صورت خودکار با ارائه‌دهنده‌های موجود کار می‌کند.

## پیکربندی ارائه‌دهنده و مدل

### تنظیمات سطح پروژه

هر پروژه TaskLoom می‌تواند یک ارائه‌دهنده و مدل پیش‌فرض داشته باشد:

1. **ارائه‌دهنده پیش‌فرض**: که برای تمام مراحل استفاده می‌شود مگر مرحله‌ای که override داشته باشد
2. **مدل پیش‌فرض**: مدل اصلی برای آن ارائه‌دهنده
3. **تنظیمات ارائه‌دهنده**: مثلاً آدرس Ollama یا endpoint خاص

### تنظیمات سطح مرحله (Stage Override)

هر مرحله SDLC می‌تواند ارائه‌دهنده و مدل مستقل داشته باشد:

| مرحله | توضیح | مثال |
|-------|-------|------|
| تحلیل | تحلیل نیازمندی‌ها | Ollama - qwen3.5:0.8b |
| بک‌اند | توسعه سرور | Codex CLI - o4-mini |
| n8n | طراحی workflow | Claude CLI - claude-sonnet-4 |
| فرانت‌اند | توسعه رابط کاربری | Ollama - llama3.1:8b |
| تست | QA و آزمون | Ollama - qwen3.5:0.8b |

### اولویت‌بندی (Priority)

هنگام تعیین ارائه‌دهنده و مدل برای هر مرحله، این اولویت رعایت می‌شود:

1. Task-level override (بالاترین اولویت)
2. Agent-level provider_override در AgentConfig
3. Stage provider در تنظیمات ai_settings پروژه
4. تنظیمات پیش‌فرض پروژه
5. Auto-detect (Ollama در دسترس → ollama، وگرنه CLI)

## کشف خودکار مدل‌ها

### Ollama
مدل‌های نصب‌شده از endpoint زیر دریافت می‌شوند:
```
GET http://localhost:11434/api/tags
```

### Codex CLI
مدل‌های موجود از Codex App Server دریافت می‌شوند:
```
codex app-server → model/list
```
این مدل‌ها شامل ID، نام نمایشی، و reasoning effort options هستند.

### Claude CLI  
Claude CLI یک endpoint کشف مدل ندارد. TaskLoom از لیست تأیید‌شده‌ای از model alias های Claude استفاده می‌کند که CLI آن‌ها را از طریق `--model` قبول می‌کند. کاربران همچنین می‌توانند هر model ID دلخواهی وارد کنند.

## قوانین اجرا

1. **هرگز fallback خاموش نیست**: اگر ارائه‌دهنده انتخابی در دسترس نباشد، مرحله fail می‌شود
2. **انتقال بین ارائه‌دهندگان ممنوع**: Ollama به Claude یا Codex به Ollama تبدیل نمی‌شود
3. **Session isolation**: هر ارائه‌دهنده session ID مستقل دارد
4. **ثبت متادیتا**: ارائه‌دهنده و مدل در تاریخچه تسک ذخیره می‌شود

## سازگاری با نسخه‌های قبلی

پروژه‌های قدیمی که از `runner=auto` یا `runner=ollama/codex/claude` استفاده می‌کنند همچنان کار می‌کنند:

- `runner=auto`: بر اساس دسترس‌پذیری ارائه‌دهنده‌ها تعیین می‌شود
- `runner=ollama/codex/claude`: به عنوان ارائه‌دهنده legacy استفاده می‌شود
- `model_settings` قدیمی: به طور خودکار به `ai_settings` جدید تبدیل می‌شود

## متغیرهای محیطی

| متغیر | توضیح | پیش‌فرض |
|-------|-------|---------|
| `OLLAMA_BASE_URL` | آدرس Ollama | `http://localhost:11434` |
| `OLLAMA_MODEL` | مدل پیش‌فرض Ollama | `qwen3.5:0.8b` |

### مراحل SDLC و مدل‌های پیشنهادی

| مرحله | وظیفه | مدل پیشنهادی |
|-------|-------|-------------|
| **تحلیل نیازمندی‌ها** | تحلیل و مستندسازی | مدل‌های بزرگتر (7B+)
| **توسعه بک‌اند** | کدنویسی بک‌اند | مدل‌های کدنویسی (Qwen, CodeLlama)
| **توسعه فرانت‌اند** | کدنویسی فرانت‌اند | مدل‌های کدنویسی (Qwen, CodeLlama)
| **مهندسی n8n** | طراحی workflow | مدل‌های عمومی (Mistral, Llama)
| **تست و کیفیت** | تست و بررسی کیفیت | مدل‌های کوچکتر (0.8B-3B)

## استفاده از رابط کاربری

### بخش تنظیمات مدل

1. به داشبورد SDLC بروید
2. روی پروژه مورد نظر کلیک کنید
3. به بخش "تنظیمات مدل‌های AI" بروید

### ویژگی‌های رابط کاربری

- **وضعیت اتصال Ollama**: نمایش وضعیت اتصال به سرور Ollama
- **لیست مدل‌ها**: نمایش مدل‌های نصب شده با اطلاعات جزئی
- **تنظیم مدل پیش‌فرض**: انتخاب مدل پیش‌فرض برای پروژه
- **تخصیص مرحله‌ای**: تنظیم مدل برای هر مرحله SDLC
- **ذخیره تنظیمات**: ذخیره تغییرات و اعمال آنها

## API Endpoints

### مدیریت مدل‌ها

```bash
# بررسی اتصال Ollama
GET /api/ollama/connection

# دریافت لیست مدل‌ها
GET /api/ollama/models

# اطلاعات مدل خاص
GET /api/ollama/models/{model_name}
```

### مدیریت تنظیمات پروژه

```bash
# دریافت تنظیمات مدل پروژه
GET /api/sdlc/projects/{project_id}/model-settings

# به‌روزرسانی تنظیمات مدل
PUT /api/sdlc/projects/{project_id}/model-settings

# دریافت مدل یک مرحله خاص
GET /api/sdlc/projects/{project_id}/stage-model/{stage}
```

## نمونه‌های استفاده

### مثال ۱: پیکربندی پروژه جدید

```json
{
  "default_model": "qwen3.5:0.8b",
  "stage_assignments": {
    "analysis": "qwen3.5:0.8b",
    "backend": "qwen3.5:0.8b",
    "frontend": "qwen3.5:0.8b",
    "n8n": "mistral:7b",
    "qa": "qwen3.5:0.8b"
  },
  "ollama_endpoint": "http://localhost:11434"
}
```

### مثال ۲: استفاده از مدل‌های تخصصی

```json
{
  "default_model": "llama3.1:8b",
  "stage_assignments": {
    "analysis": "llama3.1:8b",      // تحلیل با مدل بزرگ
    "backend": "qwen3.5:0.8b",      // کدنویسی با Qwen
    "frontend": "qwen3.5:0.8b",     // کدنویسی با Qwen
    "n8n": "mistral:7b",           // workflow با Mistral
    "qa": "gemma:7b"               // تست با Gemma
  }
}
```

## عیب‌یابی

### مشکل ۱: Ollama وصل نیست
```
خطا: "Ollama در دسترس نیست"
```

**راه‌حل**:
1. مطمئن شوید Ollama در حال اجرا است: `ollama serve`
2. آدرس را بررسی کنید: پیش‌فرض `http://localhost:11434`
3. فایروال را بررسی کنید

### مشکل ۲: مدل پیدا نمی‌شود
```
خطا: "Model 'model-name' not found"
```

**راه‌حل**:
1. مدل را دانلود کنید: `ollama pull model-name`
2. نام مدل را بررسی کنید: `ollama list`
3. در تنظیمات مدل را اصلاح کنید

### مشکل ۳: دستورات اجرا نمی‌شوند
```
خطا: "Command not allowed for security reasons"
```

**راه‌حل**:
- فقط دستورات امن مجاز هستند (npm, python, git read-only, etc.)
- از دستورات خطرناک استفاده نکنید

## بهترین روش‌ها

### ۱. انتخاب مدل مناسب
- برای کدنویسی: مدل‌های مخصوص کد (Qwen, CodeLlama)
- برای تحلیل: مدل‌های بزرگتر با context طولانی
- برای تست: مدل‌های کوچکتر و سریع

### ۲. مدیریت حافظه
- مدل‌های بزرگتر حافظه بیشتری مصرف می‌کنند
- بر اساس سخت‌افزار خود مدل انتخاب کنید
- می‌توانید از مدل‌های quantized استفاده کنید

### ۳. امنیت
- همیشه از آخرین نسخه Ollama استفاده کنید
- مدل‌ها را از منابع معتبر دانلود کنید
- دستورات خطرناک اجرا نکنید

## مهاجرت از Claude/Codex

### مزایای مهاجرت به Ollama
1. **هزینه صفر**: بدون هزینه API
2. **حریم خصوصی**: تمام پردازش‌ها محلی
3. **کنترل کامل**: انتخاب مدل دلخواه
4. **انعطاف‌پذیری**: استفاده از مدل‌های مختلف

### مراحل مهاجرت
1. Ollama را نصب کنید
2. مدل‌های مورد نیاز را دانلود کنید
3. در TaskLoom به Ollama سوئیچ کنید
4. تنظیمات مدل را پیکربندی کنید

### سازگاری عقبرو
- تسک‌های موجود با Claude/Codex همچنان کار می‌کنند
- می‌توانید همزمان از هر دو سیستم استفاده کنید
- تنظیمات پروژه‌های قدیمی حفظ می‌شود
