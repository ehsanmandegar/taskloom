Execution\n\n```\n1. USER CREATES TASK\n   ↓\n   POST /api/sdlc/tasks\n   ↓\n   SDLCTaskManager.create_task()\n   ├─ Generate unique task_id\n   ├─ Set status = \"created\"\n   ├─ Save to JSON\n   └─ Return task object\n   ↓\n2. START PIPELINE\n   ↓\n   execute_stage(task_id, \"analysis\")\n   ├─ Load task from storage\n   ├─ Set status = \"analyzing\"\n   ├─ Save task\n   └─ Start agent async\n   ↓\n3. RUN ANALYSIS AGENT\n   ↓\n   OllamaAgentRunner.run_analysis(task, project)\n   ├─ Build system prompt\n   ├─ Build user prompt (task description + context)\n   ├─ Call Ollama LLM via HTTP\n   ├─ Parse JSON response\n   ├─ Create AgentResult\n   └─ Log to structured JSON\n   ↓\n4. SAVE RESULTS\n   ↓\n   task.agent_results[\"analysis\"] = AgentResult\n   task.save_task()\n   ├─ Serialize to JSON\n   ├─ Write to data/tasks/{task_id}/task.json\n   └─ Update task.updated_at\n   ↓\n5. ADVANCE PIPELINE\n   ↓\n   _advance_or_complete(task)\n   ├─ Check next stage\n   ├─ If more stages: execute_stage(\"backend\")\n   └─ If done: status = \"pending_approval\"\n   ↓\n6. REPEAT FOR EACH STAGE\n   ↓\n   analysis → backend → n8n → frontend → qa → pending_approval\n   ↓\n7. HUMAN APPROVAL\n   ↓\n   POST /api/sdlc/tasks/{id}/approve\n   ├─ Verify status = \"pending_approval\"\n   ├─ Update status = \"done\"\n   ├─ Save task\n   └─ Return success\n   ↓\n8. TASK COMPLETE ✓\n```\n\n## Component Interaction\n\n```\n┌─────────────────────────────────────────────────────────────┐\n│                   Frontend Dashboard                         │\n│ State Machine (Task Status)\n```\ncreated\n  ↓\nanalyzing → analysis_approved\n  ↓\nbackend_running → (human_review or error)\n  ↓\nn8n_running\n  ↓\nfrontend_running\n  ↓\ntesting\n  ↓\npending_approval\n  ↓ (human clicks approve)\ndone\n```\n\n### 2. Agent Pipeline\n```\nEach agent:\n- Takes: Task + Previous results\n- Runs: Ollama LLM with context\n- Outputs: JSON (structured)\n- Stores: In task.agent_results\n- Next: Pass results to next agent\n```\n\n### 3. Async Execution\n```\nHTTP request\n  ↓ (sync)\nQueue task\n  ↓\nReturn 200 OK to client\n  ↓ (async background)\nExecute pipeline\n  ↓\nUpdate task state\n  ↓\nClient polls GET /api/sdlc/tasks/{id}\n```\n\n### 4. Structured Logging\n```\nEach operation:\n1. Log entry created (JSON)\n2. Includes: timestamp, level, logger, message, custom fields\n3. Rotating file (10MB max)\n4. Queryable via API\n5. Human-readable + machine-readable formats\n```\n\n## Deployment Architecture\n\n### Development (Local)\n```\nYour Machine\n├─ Backend (Python) :8003\n├─ Frontend (Node) :5173\n├─ Ollama :11434\n└─ Data files (./data, ./logs)\n```\n\n### Production (Docker)\n```\nContainer Host\n├─ Backend Container\n│  ├─ Python 3.12 + FastAPI\n│  ├─ Port 8003 (exposed)\n│  └─ Volumes: ./data, ./logs\n├─ Frontend Container\n│  ├─ Node build + Nginx\n│  ├─ Port 80 (exposed)\n│  └─ Proxies /api to backend\n└─ Ollama Container\n   ├─ LLM service\n   ├─ Port 11434 (exposed)\n   └─ Volumes: ollama_data\n```\n\n### Cloud (Render)\n```\nRender Deployment\n├─ Web Service (Backend)\n│  ├─ Python runtime\n│  ├─ Auto-deploy from GitHub\n│  └─ https://taskloom-backend.onrender.com\n├─ Static Site (Frontend)\n│  ├─ Node build\n│  ├─ Nginx CDN\n│  └─ https://taskloom-frontend.onrender.com\n└─ External Ollama\n   ├─ Render or other provider\n   └─ OLLAMA_HOST env var\n```\n\n## Scalability Considerations\n\n### Current (File-based)\n✓ Single instance\n✓ File I/O bottleneck ~1000 tasks\n✗ No concurrency control\n✗ No backup/recovery\n\n### Phase 2 (Database)\n✓ PostgreSQL for ACID\n✓ Connection pooling\n✓ Concurrent requests\n✗ Agent execution still single-threaded\n\n### Phase 3 (Distributed)\n✓ Multiple backend instances\n✓ Load balancer\n✓ Message queue (Celery/RQ)\n✓ Redis caching\n✓ Ollama cluster\n\n## Security Architecture\n\n```\nClient\n  ↓ HTTPS/TLS\nAPI Gateway\n  ↓ CORS validation\nBackend\n  ├─ Input validation (Pydantic)\n  ├─ Rate limiting (future)\n  └─ Error handling (no info leaks)\n  ↓\nData Storage\n  ├─ File permissions\n  ├─ No secrets in code\n  └─ Environment variables only\n```\n\n## Monitoring & Observability\n\n```\nApplication Logs\n  ↓\n┌─────────────────────┐\n│ JSON Log Format     │ → Can be shipped to ELK/Splunk\n│ - timestamp         │\n│ - level             │\n│ - logger            │\n│ - message           │\n│ - task_id (custom)  │\n└─────────────────────┘\n  ↓\nLog Query API\n  ├─ GET /api/logs → search/filter\n  ├─ GET /api/logs/stats → aggregates\n  └─ GET /api/health → uptime\n```\n\n---\n\n## Summary\n\nTask Loop uses a **layered architecture** with clear separation of concerns:\n\n1. **User Layer**: Dashboard, API, CLI\n2. **API Layer**: FastAPI routes with middleware\n3. **Business Logic**: Task/Project managers + orchestration\n4. **Agent Layer**: Ollama-powered AI agents\n5. **Persistence**: JSON files (local) / PostgreSQL (production)\n6. **External**: Ollama LLM service\n\nThis design enables:\n- ✅ Easy to understand\n- ✅ Simple to modify\n- ✅ Straightforward to scale\n- ✅ Observable and maintainable\n- ✅ Production-ready\n"}}
